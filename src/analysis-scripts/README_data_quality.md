# Timeseries Data Quality & Integrity

The preprocessing pipeline now writes a machine-readable integrity report for every processed block:

- `<block>_integrityReport.json`

It is generated by `preprocessTimeseriesData.py` and saved in the same block folder as `<block>_tsData.csv`.

## What the report includes

- **policy**: active preprocessing integrity settings (target sampling rate, event alignment tolerance, missingness thresholds)
- **timeline**: timestamp quality metrics for output timeseries (sample count, duplicates, non-monotonic steps, median `dt`, `dt` SD)
- **signals**: per-signal quality summary
  - source channel info (when available)
  - source missingness before interpolation
  - output missingness fraction
  - max allowed missingness fraction
- **event_alignment**:
  - total/aligned/unaligned events
  - alignment residuals and summary stats
  - collision count when multiple events map to the same sample
  - unaligned event details with reason (`out_of_range` or `outside_tolerance`)
- **status**: `pass`, `fail`, or `error`
- **fail_reasons**: explicit reasons used for quality gating

## Current integrity policy (defaults)

- Resampling target: `200 Hz`
- Event-to-sample tolerance: `25 ms`
- Missingness thresholds:
  - `pupilDiameter`: `0.40`
  - `IBI`: `0.30`
  - `SD_RR`: `0.40`
  - `SCR`: `0.35`
  - `RESP`: `0.35`
  - default: `0.40`

## Notes

- Pupil blink/missing segments remain `NaN` in outputs and are explicitly quantified in QA.
- Event alignment is nearest-neighbor **with tolerance**; events outside tolerance are reported as unaligned.
- If an exception occurs during block processing, an integrity report is still attempted with `status: error`.
